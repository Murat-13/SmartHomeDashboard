## Что сделано

- **Вход** (`DigestAuth`): Digest MD5 и SHA-256, `-sess`, Basic — по порядку; несколько предложений сразу; «nonce устарел» — ещё
  раз, это не неверный пароль. Пароль открытым текстом — только если камера другого не умеет.
- **RTSP** (`RtspSession`):
  - чужой адрес в Content-Base и `control` (0.0.0.0, старый IP) — путь камеры, узел наш;
  - OPTIONS не понимают; PLAY и SETUP только по другому варианту адреса;
  - звук объявлен, но не отдаётся — видео важнее;
  - перенаправление регистратора — только внутри домашней сети, не больше трёх раз;
  - камера спрашивает внутри потока — получает ответ (без него часть камер рвёт сессию);
  - мусор и лишние переводы строк между кадрами; RTCP в канале RTP; каналы назначает камера;
  - keep-alive с новым nonce — повтор сразу; молчащая сессия разговора держится запросами.
- **Кадры** (`VideoDepacketizer`): маркер на SPS/PPS, несколько NAL в одном пакете, стартовые коды и лишние наборы в `sprop` —
  плеер получает ровно SPS и PPS (Media3 иначе отвергает описание).
- **Показ своим клиентом**: встроенный плеер (Media3) не умеет TLS, SHA-256 и части странностей. Две неудачи подряд — видео
  держит общий поток `CameraHub` сам (`hold`), а плеер смотрит через планшет, как при записи. `rtsps` — сразу так. У камеры,
  которую пишет планшет, ничего не меняется. Не вышло и так — снова напрямую.
- **TLS** (`CameraTls`): сертификат камеры запоминается при первом подключении на этом планшете; подменённый — отказ. Сохранить
  камеру в редакторе — запомнить заново. В копии не входит.
- **Камеры только со снимком** (`CameraSnapshot`): адрес снимка даёт камера (ONVIF `GetSnapshotUri`) или вводит человек; раз в 5 с на
  плитке и раз в секунду в раскрытой; только домашняя сеть. Записи и HD у такой камеры нет.
- **Разговор** (`HttpTalk`, docs/talk-tz.md, «Hikvision и Dahua»): запасной путь, когда обратного канала ONVIF нет.

## Чем проверяется

- `CameraQuirksTest` (JVM) — поддельная камера на каждую странность; идёт на GitHub при каждом изменении (Android CI). TLS —
  настоящий, со своим сертификатом.
- `HttpTalkTest`, `CameraSnapshotTest`, `RecordingHubTest` — разговор, снимки, общий поток.
- `CameraBrandsDeepTest` (эмулятор, Deep tests) — настоящая плитка: камера с SHA-256, чужие адреса и вопросы внутри потока,
  камера только со снимком.
- `tools/camera-stand` — стенд на Mac с настоящим H.265/H.264 (docs/camera-stand.md).

## Не сделано

- AAC в динамик Hikvision (у новых камер), G.722 — только G.711.
- Отчёты RTCP RR (Arlo Pro 2 рвёт без них), SRTP, RTSP поверх HTTP и UDP.
- Свой HTTP-порт камеры для разговора: только 80.
