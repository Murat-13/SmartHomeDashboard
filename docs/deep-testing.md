# Глубокие проверки (0.9.13)

Задача владельца 07.11.2026 (вариант C): максимум бесплатных автоматических проверок, найденные дефекты исправить.
Всё работает в GitHub Actions публичного репозитория, без оплаты и без секретов. Реальный дом, Home Assistant,
камеры и планшеты не затрагиваются: только искусственные сущности, фальшивый HA и тестовые ролики.

Workflow: [.github/workflows/deep-tests.yml](../.github/workflows/deep-tests.yml). Ручной запуск — вкладка Actions →

(Summary) и в артефакте `emulator-report` (`deep-log.txt`); отчёт хаоса — артефакт `chaos-report`.

## Запуск локально

```bash
./gradlew testDebugUnitTest --tests '*PanelChaosTest*' -Pchaos.iterations=1500   # больше сочетаний
./gradlew testDebugUnitTest --tests '*PanelChaosTest*' -Pchaos.seed=7919         # повтор одного сочетания из отчёта
./gradlew connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.example.smarthomedashboard.deep.PanelEndToEndTest
```

Отчёт хаоса: `app/build/reports/chaos/panel-*.txt` — сбои сгруппированы по месту в коде, с сидами для повтора.
Тесты эмулятора с RTSP требуют аргумент `rtspHost` (адрес машины со стендом, для эмулятора — `10.0.2.2`);
без него пропускаются. Soak — только с аргументом `soakMinutes`.

**Только эмулятор.** Тесты `deep/` заменяют настройки и плитки приложения искусственными, поэтому на физическом
устройстве пропускаются (проверка `isEmulator()`, а `prepareApp` вдобавок прерывает тест до записи). Но сам Gradle
после `connectedDebugAndroidTest` удаляет приложение вместе с данными на любом устройстве — на настенном планшете
эту команду не запускать.

## Скриншот-эталоны

Визуальные тесты (`*VisualTest`, `*LookTest`, `PowerGraphTest`, `SettingsSectionsTest`, `ModernDesignSystemTest`)
сверяют рендер с эталоном в `app/src/test/golden/<группа>/<имя>.png`. Допуск — сглаживание: пиксель «другой» при
разнице канала больше 40, рендер «другой» при доле таких пикселей больше 0,4 %. Карта отличий —
`app/build/reports/golden-diff`. Намеренное изменение вида — новые эталоны:

```bash
./gradlew testDebugUnitTest -Pgolden.record
```

Сравнение только на Linux (эталоны сняты там, как и в CI): на Mac рендер шрифтов другой, проверка там пропускается.
Без эталона: плитка часов и климата (`home-climate-visual`) и график мощности (`power-graph`) — показывают настоящее
время; экраны настроек (`settings-sections`) — итог проверки обновлений зависит от сети.

## Образцы совместимости

`app/src/test/resources/compat/v*.json` записаны настоящим кодом прежних версий: в рабочей копии тега временно
запускался генератор, который создаёт плитки всех типов, существовавших в этой версии, её же шаблонами
(`newTileConfig`) и пишет `dashboard_prefs`, `tiles_prefs` и файл резервной копии (`ConfigBackup.build`).
Сущности и адреса искусственные. При изменении формата добавляйте образец новой версии; старые не удаляйте.

## Найдено и исправлено (0.9.13)

| Находка | Чем найдено | Последствие до исправления | Исправление |
|---|---|---|---|
| Состояние «NaN»/«Infinity» в сенсоре «Инвертора» | хаос панели | исключение `BigDecimal` в главном потоке — приложение падает | `BatteryFormat.decimal` и код флага: не число → «—» |
| Точность датчика −1 или огромная (импорт копии, старые данные) | хаос панели (крайние числа) | `IllegalFormatException` на панели — падение; огромная — строка на гигабайты | точность 0–6 при показе; редактор по-прежнему предупреждает |
| Размер текста плитки 0, отрицательный, сотни тысяч (импорт, экран расширенных настроек без проверки) | хаос панели | разметка огромного текста подвешивает главный поток | 1–200 при показе и при сохранении расширенных настроек |
| Граница правила напряжения «Электропитания Modern» — не число | хаос редакторов | редактор падал при повороте/сворачивании (`Forbidden numeric value: NaN`) | такое правило пропускается при чтении |
| Камера принимает соединение и молчит | анализ Media3 при подготовке RTSP-стенда, проверка на эмуляторе | «Подключение…» навсегда, без повторов | 20 с без первого кадра — неудачная попытка, обычный цикл повторов |
| NaN в подписях климата и графика | хаос панели (защита) | возможное исключение `BigDecimal` | «—» |

Утечек памяти в коде приложения не найдено: старые экраны после 6 пересозданий освобождаются полностью (эмулятор),
статические реестры (домофон) отписываются в `onDestroy`. Нехватка памяти в длинных JVM-прогонах оказалась
особенностью Robolectric (держит созданные экраны и показанные Toast) — тесты чистят это сами.

## Итоги прогонов 07.11.2026

- Хаос панели: 1500 сочетаний — 0 сбоев (до исправлений — падения на NaN в «Инверторе»).
- Хаос редакторов: 500 сочетаний на каждый из 5 редакторов — 0 сбоев (до исправления — 21 падение «Электропитания»).
- Фальшивый HA с мусором: 75 000 сообщений — ни одного падения, каждая команда получила ровно один итог.
- Совместимость: v0.9.1, v0.9.4, v0.9.8 — все плитки читаются, строятся и обновляются, старые копии импортируются.
- Эмулятор (Android 14, Pixel C, программная отрисовка): запуск со всеми типами плиток без команд устройствам;
  шторм событий с раскрытиями — без падений, главный поток отвечает (кадры эмулятора медленные: это не замер
  планшета); обрыв и возврат связи ×3 — переподключение без перезапуска; пересоздание экрана — одно соединение;
  старых экранов в памяти — 0 из 6.
- Домофон на RTSP-стенде (тестовые ролики H.264): субпоток 640×480 на плитке играет; после раскрытия основной поток
  1080p подхватывается с надписью «HD»; закрытый порт, «адрес в никуда» и молчащая камера — без подвисаний
  (максимум 116–149 мс между кадрами), каждая попытка заканчивается ошибкой и повтором (молчащая — через 20 с).
- Поток 2560×1920 H.264 на эмуляторе **играет** (программный декодер эмулятора). Значит, сам приложение и Media3
  такой поток принимают; отказ на Samsung выше 1080p — вероятнее, ограничение аппаратного декодера планшета
  (предположение, на планшете не проверялось).
- detekt: 14 находок, ни одной настоящей ошибки (неявная локаль в `#%08X` и т. п.) — приняты в baseline.
- Не проверено: физический планшет; первый ночной soak (120 мин) — по расписанию.
