# Обновления через GitHub Releases (этап 09б)

Приложение само находит и скачивает новую версию, проверяет её, но **пока не устанавливает** — установка
будет на этапе 09в. Подпись и версии — [release-signing.md](release-signing.md).

## Как это работает на планшете

- Источник — публичный репозиторий `Murat-13/SmartHomeDashboard`, API
  `https://api.github.com/repos/Murat-13/SmartHomeDashboard/releases`. Токен не нужен.
- **Каналы** («Настройки → О приложении»; по умолчанию — стабильный):
  - тестовый видит все выпуски;
  - стабильный — только выпуски **без** флажка «Set as a pre-release».
  Канал — настройка конкретного планшета: в экспорт и автокопии не входит.
- Проверка: раз в 6 часов при наличии сети (WorkManager, первая — через ~10 мин после запуска панели)
  и кнопкой «Проверить сейчас». Выбирается самый новый выпуск канала, который новее установленного.
- Проверки скачанного файла, по порядку:
  1. загрузка только по HTTPS и только с доменов GitHub, в том числе после переадресаций (в коде,
     т. к. `network_security_config` разрешает HTTP ради локального HA); не больше 100 МБ; хватает места;
  2. SHA-256 совпадает с хэшем выпуска (поле `digest`, которое GitHub считает сам, или файл `<apk>.sha256`);
  3. внутри APK: то же приложение (`com.example.smarthomedashboard`), versionCode = версии из тега,
     **сертификат подписи совпадает с установленным приложением**.
  Не прошёл — файл удаляется, причина видна в «О приложении». Отвергнутый по пакету/версии/подписи
  выпуск повторно не скачивается, пока на GitHub не появится другой файл.
- Готовый файл лежит во внутренней папке приложения (`no_backup/updates`, не попадает в облачный бэкап).
  В боковой панели появляется строка «Доступно обновление X». Сбой GitHub или сети уже скачанное не отменяет.
- Всё выполняется в фоне. Недоступный GitHub, обрыв сети, нехватка места или неверная подпись становятся
  статусом и не мешают управлять домом.
- Копия «перед обновлением» (`smarthome_preupdate_<дата>_to_<версия>.json`, 2 последние, в той же папке, что
  автокопии) готова в коде (`AutoBackup.beforeUpdate`), а делаться будет в момент установки (09в), чтобы
  отражать настройки на момент обновления, а не на момент загрузки.

⚠ Пока планшет не переустановлен с новым ключом, его приложение подписано отладочным ключом. Выпуски с
release-подписью он будет отвергать: «подпись … не совпадает с установленным приложением». Так и должно быть.

## Как выпустить новую версию (делает владелец)

1. В `app/build.gradle.kts` поднять `appVersionName` (например, `0.9.1`), закоммитить.
2. Собрать: `./gradlew assembleRelease` (с `keystore.properties`), проверить подпись (`apksigner verify --print-certs`,
   см. release-signing.md), переименовать `app/build/outputs/apk/release/app-release.apk` в
   `SmartHomeDashboard-0.9.1.apk`.
   Загружать только **release**-APK: debug при наличии ключа подписан тем же ключом и тоже прошёл бы проверку.
3. По желанию — файл хэша: `shasum -a 256 SmartHomeDashboard-0.9.1.apk > SmartHomeDashboard-0.9.1.apk.sha256`.
4. GitHub → Releases → «Draft a new release»: тег **`v0.9.1`** (ровно как `appVersionName`, с `v`), ветка `main`,
   описание изменений, прикрепить **один** `.apk` (и при желании `.sha256`), отметить **«Set as a pre-release»**,
   «Publish release». Тестовый канал (Москва) увидит его при следующей проверке.
5. Через 3+ дня работы без замечаний: открыть выпуск → «Edit» → снять «Set as a pre-release» → «Update release».
   Теперь его видит и стабильный канал.

Правила: номер версии не переиспользовать; не заменять APK в уже опубликованном выпуске (выпустите следующую
версию); выпуск с двумя `.apk` или тегом не вида `vX.Y.Z` приложение пропускает. Репозиторий публичный — APK
может скачать кто угодно; секретов в нём нет (токен, ключ Яндекса и PIN вводятся на планшете).
