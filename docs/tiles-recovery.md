# Повреждённые плитки и восстановление (0.9.2, этап 1)

## Что было

`TileManager.loadTiles()` разбирал `tiles_prefs/tiles` через `Gson.fromJson` без обработки ошибок: битый JSON,
`null`, не-массив или `null`-элемент роняли панель при запуске (в режиме «главный экран» — по кругу). Gson без
конструктора оставлял в отсутствующих полях `null`/`0`/`enabled=false` вопреки значениям по умолчанию Kotlin.
Ежедневная автокопия копировала повреждённую строку как есть и за 3 ночи вытеснила бы все исправные копии.

## Как теперь

- **Чтение** — `data/TileParser`: формат тот же, разбор поэлементный. Корень не массив / битый JSON / `null` —
  пустой список и признак «не прочитано». `null`- и не-объектные элементы и плитки без непустых `id`/`type`
  пропускаются (остальные показываются); порядок и повторы `id` — как раньше. Отсутствующие или неверного типа поля получают
  значения `TileEntity` по умолчанию: `appearance/conditions/config` `{}`, `collapsedSensorIds/colorRules` `[]`,
  `icon` `""`, `sourceType` `auto`, `enabled` `true`, `container` `grid`; `fontSize` ≤ 0 → 16, `page` < 0 → 0,
  нецелые числа → 0 (`width/height` → 1, они в отрисовке не используются). Исправные данные читаются без изменений.
- **Оригинал не теряется.** Чтение ничего не записывает. При обнаружении повреждения исходная строка
  копируется в `files/backups/tiles_damaged_<время>.json` (3 последних, та же строка — один раз; папка исключена
  из облачного бэкапа Android — этап 3). Любая запись плиток при повреждённых данных сначала проверяет, что
  оригинал сохранён; не удалось — запись не выполняется.
- **Стартовые плитки** («Часы», «Погода») не создаются поверх повреждённых данных; приветствие новой установки
  не показывается.
- **Автокопии** (`AutoBackup.run`) при повреждённых плитках не создаются (`Outcome.DAMAGED`, статус «Бэкап:
  пропущен — плитки повреждены»), исправные копии не вытесняются. **Копия перед обновлением** в этом случае не
  считается сделанной — установка встаёт на паузу (продолжить без копии можно только по PIN с предупреждением).
- **Сообщение на панели** (решение владельца): диалог «Плитки повреждены» — сколько не прочитано, что оригинал
  сохранён; «Восстановить…» (PIN → «Настройки → Устройство») или «Позже». Исправные плитки работают, редактировать
  панель можно (решение владельца): сохраняются только исправные плитки, оригинал уже лежит отдельным файлом.
- **Восстановление** — «Настройки → Устройство → Восстановить из копии»: список ежедневных копий и копий «перед
  обновлением» (текущая папка копий и внутренняя папка приложения), новые сверху → подтверждение → тот же путь,
  что «Импорт из файла» (`applyImport`: строгая проверка, токен/ключ Яндекса/PIN не меняются, другой адрес HA —
  только по согласию и после проверки подключения) → перезапуск панели. Копий нет — предложение импорта файла.
