# Потребляемая мощность на кнопках Modern

Реализовано по требованиям владельца из сообщения от 30.10.2026 и приложенному
эскизу. Владелец подтвердил, что отдельный файл ТЗ содержит тот же текст.
Начальная рабочая копия main была чистой после `34dfc92`.

## Настройки и поведение

- По умолчанию показ мощности выключен у всех кнопок, включая новые, розетки,
  реле и детей группы. Автоматического включения по домену или атрибутам нет.
- У одиночной Modern-кнопки в редакторе появился блок «Потребляемая мощность»:
  переключатель «Показывать мощность», поле «Сущность мощности Home Assistant»,
  список сенсоров с поиском по любой части имени/entity_id и ручной ввод.
  При выключенной опции поле и список скрыты.
- У детей Modern-группы отдельная кнопка настроек в каждой строке списка устройств.
  Диалог содержит тот же блок и полноразмерный предпросмотр. «Применить» меняет
  только черновик списка; в хранилище он попадает по общей кнопке «Сохранить».
  «Отмена» диалога и «Не сохранять» списка оставляют исходные настройки.
- Черновики одиночной кнопки, списка детей и открытого диалога переживают
  пересоздание Activity. Пустой включённый источник нельзя сохранить/применить.
- Строка с контурной молнией появляется под названием только у полноразмерной
  одиночной/дочерней Modern-кнопки. Иконка и внутренние отступы уменьшаются только
  при включённой опции. Без неё сохраняются прежние параметры отрисовки.
  Размеры, координаты, рамка, скругления и область нажатия не изменены.
- Материнская плитка группы, её миниатюры и Classic мощность не рисуют.
  Суммирование не добавлено. Иконки группы и детей продолжают работать как раньше.

## Хранение

Внутри существующего `TileEntity.config`, без миграции общего формата:

```json
{
  "show_power": true,
  "power_entity_id": "sensor.example_power"
}
```

Отсутствующие поля означают false и пустую строку. Обычное сохранение старой
плитки не добавляет эти поля, пока пользователь не изменит настройку мощности.
У группы используется отдельная карта `child_power`:

```json
{
  "child_power": {
    "switch.example": {
      "show_power": true,
      "power_entity_id": "sensor.example_power"
    }
  }
}
```

Ключ карты — управляющий entity_id ребёнка, а не номер строки. Перестановка
перемещает весь объект ребёнка вместе с его настройками. Удаление удаляет его
настройки; замена на другое устройство сбрасывает мощность в OFF, повторный выбор
того же устройства сохраняет её. Самостоятельные плитки той же сущности не меняются.
Остальные поля config сохраняются существующим механизмом.

## Данные HA и обновления

Используется только существующее соединение MainViewModel. Оно уже подписано
на все `state_changed` и получает `get_states` после подключения/восстановления.
Новый WebSocket, REST-опрос и таймер запросов не создавались. Сам транспорт не изменён.

Существующий `PanelEntityIds` обходит строки config, включая вложенную карту
`child_power`, поэтому выбранные сенсоры автоматически входят в `PanelDependencyIndex`.
Событие сенсора адресно обновляет модель соответствующей кнопки/группы. Раскрытые
дети сравнивают модель с предыдущей и перепривязываются только при изменении;
материнская плитка при изменении только мощности имеет прежнюю модель.
Всё дерево дашборда не пересоздаётся.

Значение берётся из состояния выбранного sensor.*, единица — из его атрибутов.
ON/OFF управляющей сущности не участвует в вычислении мощности. Поддерживаются
W/kW и русские Вт/кВт: ниже 1000 Вт — целые ватты, начиная с 1000 Вт — кВт с
округлением до двух знаков и без лишних конечных нулей. Например: 0 Вт, 648 Вт,
1,82 кВт. Отрицательное числовое значение сохраняет знак.

unknown/unavailable, отсутствующие/устаревшие данные, неподдерживаемая единица
(включая Wh/kWh) и device_class=energy дают «— Вт». Разрыв связи использует
существующий staleEntities; новые события/снимок снимают недостоверность.
Патологические числовые строки/экспоненты и значения выше ±1 ГВт дают прочерк.

## Ограничения и что не проверено

- Физический планшет, реальный HA, полный перезапуск процесса на устройстве,
  инструментальные тесты на устройстве и длительное профилирование не проверены.
  Команды дому, установка и push не выполнялись.
- При недоступном HA ручной ввод проверяет синтаксис sensor.*; подтвердить
  наличие/единицу сущности до получения её атрибутов невозможно. При получении
  несовместимой единицы показания остаются прочерком; при доступных атрибутах
  такой сенсор также исключается из списка и не проходит валидацию сохранения.
- Список выбора использует имеющиеся данные и кеш имён; отдельное сетевое
  обновление списка намеренно не добавлено. Отсутствующий в списке новый сенсор
  можно ввести вручную.
