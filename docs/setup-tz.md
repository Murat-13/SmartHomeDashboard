# ТЗ: простая первая настройка и планшет 24/7

Статус: **ждёт утверждения владельцем (24.11.2026)**. Код не начат.

## Задача владельца (24.11.2026)

Приложение может выйти в массы. Сейчас его может настроить только тот, кто знает, где в Home Assistant взять токен и
как выглядит адрес RTSP. Нужна первая настройка, с которой справится обычный человек.

Слова владельца о планшете: приложение рассчитано на работу 24/7 на стене, планшет всегда подключён к сети, на
большинстве устройств можно включить лимит заряда ≈ 80 %. Расход батареи в обычном сценарии не волнует, а **нагрев важен**.

## Что сейчас (0.9.58)

| Шаг | Как сделано | Что мешает новому человеку |
|---|---|---|
| Найти Home Assistant | адрес вводится руками (`SetupActivity`) | нужно знать IP и порт |
| Войти | длинный токен создаётся в профиле Home Assistant и переносится на планшет | никто, кроме опытных, этого не знает; 180+ символов на настенном планшете |
| Первые плитки | часы и погода (`createStarterTilesOnFirstLaunch`), остальное — по одной | десятки ручных действий |
| Камера | адрес вводится руками, дальше `Onvif.probe` находит потоки | нужно знать IP камеры |
| Остаться на экране | «главный экран» и киоск — переключатели в Настройках | про них никто не узнает |
| Android не убивает приложение | не проверяется и не подсказывается | у Xiaomi, Huawei, Samsung это делается по-разному |
| Заряд и нагрев | нагрев виден на экране «Планшет», при сильном — облегчённый режим | лимит заряда не проверяется |
| Новый планшет вместо старого | настройка с нуля, потом импорт файла в Настройках | «восстановить» на первом экране нет |

## Решения владельца (24.11.2026)

1. **Вход** — обычная страница входа Home Assistant на планшете **и** вход с телефона по QR. Ввод токена — запасной.
2. **Первые плитки** — предложить по комнатам, списком с галочками.
3. **Второй планшет** — файл копии на первом экране сейчас; копирование с другого планшета по QR — последним этапом.
4. **Стенд** — настоящий Home Assistant на Mac (скачан, отдельная папка вне репозитория).
5. **Нагрев** — советы, а при перегреве панель остывает сама.
6. **Новый адрес Home Assistant** — спросить на экране.
7. **Возврат панели** — главный экран Android и проверка перезагрузкой; запасной способ — «поверх других окон».

## Проверено до ТЗ

### Вход — на настоящем Home Assistant 2026.11.3 (стенд на Mac, только localhost)

- Адрес планшета в домашней сети годится как `client_id` и адрес возврата (`http://<планшет>:<порт>/`): свой сайт и
  интернет не нужны. Чужой адрес возврата — отказ 403.
- PKCE (S256) работает: с чужим проверочным кодом — «Invalid code verifier».
- По временному доступу создаётся постоянный (`auth/long_lived_access_token`); он работает и после отзыва временного.
  То же имя второй раз — ошибка («unknown_error»), поэтому имя должно быть уникальным.
- Обычный пользователь (не администратор) может всё, чем пользуется панель: состояния, события, история, списки
  сущностей, устройств и комнат. Нельзя только одно: подписка на кнопки уведомлений телефона («Открыть» калитку из
  уведомления) — `unauthorized`.
- mDNS `_home-assistant._tcp`: название, `uuid` и версия; `internal_url` — есть, `external_url` — пустой, если не задан.

### Поиск камер — в домашней сети, только чтение, без паролей

- WS-Discovery (ONVIF): домофон ответил через 0,05 с, название модели — в ответе.
- Поиск Reolink (UDP 2000 → 3000): ответ через 0,01 с. Нужен для камер Reolink с выключенным ONVIF.
- Home Assistant сам знает адреса камер: `config/device_registry/list` (без прав администратора) отдаёт
  `configuration_url`, производителя и модель. Паролей и ссылок RTSP не отдаёт.

### Планшет — московский Samsung, Android 16, One UI 8 (adb, только чтение)

- Лимит 80 % включён: `status = NOT_CHARGING` при 79 % на USB; аккумулятор 28 °C, процессор 45–50 °C, нагрев в норме.
- Приложение не в списке исключений экономии батареи, но «активное» (ведро 10): недели работы без убийств.
- Заставка выключена, «не выключать экран при зарядке» включено.

### Android — по документации и сайтам марок (полный список источников — в конце)

- Пока планшет на зарядке, Android почти не ограничивает приложения. Ловушка: при лимите 80 % Android в некоторые минуты
  может считать планшет «не заряжается» — тогда ночные задачи подчиняются квотам, как на батарее. Исключение из
  экономии батареи и служба записи это смягчают.
- Узнать, включён ли лимит заряда, официально нельзя — только наблюдать (подключён, 75–85 %, «не заряжается» часами).
- Экраны автозапуска Xiaomi/OPPO и «Запуск приложений» Huawei открываются ненадёжно; их состояние прочитать нельзя.
  У Samsung есть официальный переход к списку «никогда не усыпляемых».
- Главный экран Android открывается сам после перезагрузки. Часть Lenovo после перезагрузки сбрасывает выбор.
- С Android 15 у приложений не из магазина разрешение «поверх других окон» спрятано за «Разрешить ограниченные
  настройки».

## Мастер первой настройки

Новый экран вместо нынешнего `SetupActivity` (Modern, Views — как остальные редакторы), работает в обоих положениях и от
360 dp. Каждый шаг можно пропустить, «Назад» возвращает на шаг раньше, закрытие и поворот не теряют сделанного.

| Шаг | Что делает человек | Что делает панель |
|---|---|---|
| 0. Начало | «Новая панель» / «Восстановить из файла копии» / позже — «Скопировать с другого планшета» | — |
| 1. Home Assistant | касается найденного или вводит адрес | ищет в сети, показывает название, версию и адрес |
| 2. Вход | входит на планшете, с телефона по QR или вставляет токен | получает постоянный доступ, проверяет подключение |
| 3. Комнаты | снимает лишние галочки | предлагает плитки и раскладывает их |
| 4. Камеры | касается найденной, вводит логин и пароль | проверяет потоки, показывает картинку, ставит плитку |
| 5. Планшет | проходит список проверок | открывает нужные экраны Android, проверяет, что сделано |
| 6. Защита | задаёт PIN, выбирает папку копий (по желанию) | — |
| 7. Готово | — | итог: что сделано, что пропущено и где это найти |

- На уже настроенных панелях мастер не показывается и ничего не меняет. Отдельные части доступны из Настроек: вход
  («Соединения» → «Войти заново»), «Найти камеры» (при добавлении плитки), «Проверка планшета» (экран «Планшет»).
- Прерванный мастер продолжается с того же шага.

## Часть 1. Поиск и вход

### Поиск Home Assistant

- mDNS (`NsdManager`) сразу; через 3 с параллельно — `homeassistant.local:8123` и `homeassistant:8123`; по кнопке
  «Искать дальше» — порт 8123 в своей подсети (до 254 адресов, только соединение).
- Адрес: `internal_url`, если отвечает; иначе адрес устройства из mDNS и его порт. Запасной адрес — `external_url`, если
  он https.
- Несколько Home Assistant — список. Ни одного — понятный текст, что проверить (тот же Wi-Fi, гостевая сеть, роутер), и
  поле адреса.
- Ненастроенный Home Assistant (`onboarding_required`) — «Сначала закончите настройку самого Home Assistant».

### Вход на планшете

- Страница `/auth/authorize` в отдельном окне (WebView без моста JavaScript, без доступа к файлам; cookie и хранилище
  очищаются после входа). `client_id` — адрес самого Home Assistant, переход на адрес возврата перехватывается.
- Двухфакторный вход и «доверенные сети» — как обычно на этой странице.
- Старый WebView или ошибка сертификата — понятный текст и предложение войти с телефона. Проверка сертификатов не
  ослабляется.

### Вход с телефона (QR)

- Планшет на время экрана открывает в домашней сети одноразовую страницу (случайный порт, случайный путь 128 бит) и
  показывает её QR. QR рисует сам (без новых библиотек).
- Телефон открывает её и переходит на страницу входа Home Assistant; после входа Home Assistant возвращает телефон на
  планшет с одноразовым кодом. Планшет меняет код на доступ (PKCE: перехваченный код бесполезен), телефону показывает
  «Готово, вернитесь к планшету».
- Страница закрывается после входа, по уходу с экрана и через 10 минут.
- Телефон не в той же сети — страница не откроется; на планшете подсказка.

### Доступ

- После входа создаётся постоянный доступ с именем «Панель — <модель планшета> — <дата и время>», временный отзывается.
  Хранится в том же слоте, что и токен сейчас (`HaTokenAccess`): формат секретов и подключение **не меняются**.
- В Home Assistant он виден в профиле («Долгосрочные токены доступа»), его можно отозвать. Отозвали — «Войти заново».
- Совет в мастере: завести для панели отдельного пользователя без прав администратора. Не хватать будет только кнопки
  «Открыть» в уведомлении телефона.
- Неверный пароль — не больше трёх попыток подряд без паузы: Home Assistant может заблокировать адрес планшета.

### Новый адрес

- Панель запоминает `uuid` Home Assistant (без адреса в журнале). Локальный адрес не отвечает 2 минуты, а тот же `uuid`
  виден в сети по другому адресу — плашка «Home Assistant найден по новому адресу. Переключиться?» (при включённом PIN —
  с PIN). До ответа токен на новый адрес не уходит.

## Часть 2. Первые плитки по комнатам

- Источник: комнаты, этажи, устройства и сущности Home Assistant (`list_for_display`, `device_registry`,
  `area_registry`, `floor_registry`); сущность без комнаты берёт комнату устройства.
- Не предлагается: служебное (`entity_category`), скрытое и отключённое в Home Assistant, недоступное, автоматизации,
  скрипты, обновления.
- Что чем становится:

| В Home Assistant | Плитка |
|---|---|
| свет, розетки, выключатели, вентиляторы | кнопка Modern; в комнате больше трёх светильников — группа «Свет · <комната>» |
| температура и влажность комнат, погода | одна «Часы · Погода · Климат дома» |
| замки, ворота, гаражные двери | проход («Калитки и ворота») и его плитка — с удержанием, как сейчас |
| камеры и домофоны | шаг «Камеры»; не найдены в сети — плитка через Home Assistant (HLS или снимок) |
| накопитель, инвертор, сеть | не предлагается сама: редакторы требуют выбора ролей; в конце — подсказка, где добавить |

- На экране: комнаты с галочками, у каждой — число плиток; внизу — сколько страниц получится. По умолчанию отмечено не
  больше, чем входит на главную и две страницы.
- Раскладка без наложений (`TilePlacement`) по размеру экрана планшета; главная — климат, камеры, проходы и общий свет,
  дальше — по комнатам. В книжном положении — нынешняя автоматическая.
- Ничего не переключается: только создаются плитки. «Убрать предложенные плитки» — одной кнопкой, пока панель не правили.

## Часть 3. Поиск камер и домофонов

- Где: шаг мастера и кнопка «Найти камеры» в редакторе «Камеры» и «Домофона».
- Как (только чтение, без паролей), одновременно, 5 с:
  1. WS-Discovery: типизированный и общий запрос, трижды;
  2. поиск Reolink;
  3. устройства Home Assistant (`configuration_url`) — находит и камеры в другой подсети.
- Одна камера из нескольких источников — одна строка: модель, марка, адрес; уже добавленные — с пометкой.
- Не нашлось — ввод адреса и подсказка, где у этой марки включается ONVIF или RTSP (Reolink, Hikvision, Dahua, Tapo,
  EZVIZ, Imou, Uniview, Axis). Тексты — только подтверждённые источниками.
- Дальше как сейчас (`Onvif.probe`): логин и пароль → модель и потоки. Перед сохранением — живая картинка и короткая
  проверка из диагностики (декодер, частота, размер).
- Следующей камере предлагается тот же логин и пароль — кнопкой. Сама панель пароли не подбирает: камеры блокируют вход.
- Домофон отличается по модели (слова Doorbell, VDB, Intercom) — только предположение, тип плитки выбирает человек.

## Часть 4. Планшет 24/7

Экран «Планшет» получает раздел **«Проверка планшета»**; он же — шаг 5 мастера. Каждая строка: «в порядке» / «сделайте»
/ «нельзя проверить», совет и кнопка, которая открывает нужный экран Android. Строка в боковой панели — только если
что-то действительно мешает (правило 10 минут, как у советов камер).

### Чтобы Android не убивал приложение

| Проверка | Как узнаём | Что предлагаем |
|---|---|---|
| Экономия батареи | `isIgnoringBatteryOptimizations` | список исключений Android (`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`, без нового разрешения) |
| Ограничение в фоне | `isBackgroundRestricted`, `getAppStandbyBucket` | экран приложения |
| Автозапуск и «спящие» приложения марки | прочитать нельзя | переход для марки (Samsung — официальный, остальные — если экран есть, иначе настройки приложения), пошаговый текст; человек отмечает «сделал» |
| Нас убивали | `getHistoricalProcessExitReasons` при запуске (Android 11+) | «За 7 дней Android закрыл приложение N раз» и совет для марки |
| Ночные задачи | время последнего запуска (уже есть у копий) | если не было больше 48 ч — совет |

Расход батареи не показывается и не экономится: планшет всегда на зарядке.

### Чтобы панель возвращалась

- «Главный экран» (`HomeScreenMode`) — рекомендуется на шаге мастера, выбор подтверждает человек в окне Android.
- «Проверить перезагрузкой»: панель запоминает момент, человек перезагружает планшет; после запуска видно, открылась ли
  она сама и за сколько. Не открылась — запасной способ «поверх других окон» с объяснением «Разрешить ограниченные
  настройки» (Android 15+). Разрешение просится только в этом случае.
- Блокировка экрана PIN-кодом Android мешает возврату — проверка `isDeviceSecure()` и совет.
- Заставка Android и Daily Board (Samsung): заставка включена или появилась поверх панели — совет, где выключить.

### Заряд

- Лимит заряда определяется наблюдением: подключён, 75–90 % и «не заряжается» — «лимит работает»; больше 24 ч ≥ 95 % на
  зарядке — «сделайте» с путём для марки (Samsung: Батарея → Защита аккумулятора → Максимальная 80 %; Huawei, Xiaomi,
  Lenovo, Pixel Tablet — свои).
- Нет такой настройки — честно «на этом планшете нет» и совет: не держать в жаре, зарядка не быстрая.

### Нагрев

- Показ: температура аккумулятора сейчас, максимум за сутки и за неделю; состояние нагрева Android. История — числа в
  памяти приложения, без новых файлов в копии.
- Совет: аккумулятор ≥ 40 °C дольше 10 минут — «тепло», ≥ 45 °C — «слишком горячо» (солнце, закрытая рамка, быстрая
  зарядка). Пороги — наш выбор: официального предела для постоянной зарядки не нашлось; уточнить на планшетах.
- Остывание само: при «тепло» (и при сильном нагреве Android — как сейчас) — облегчённый режим; при «слишком горячо» —
  ещё и яркость панели ниже на четверть и частота экрана 60 Гц (`preferredRefreshRate`), если экран быстрее. Снимается,
  когда остыло на 3 °C и прошло 10 минут. Звонок, запись, разговор и задержка видео не меняются.
- До включения — замер на московском планшете (экран 90 Гц): сколько даёт 60 Гц и яркость; не даёт — не делаем.

### Экран

- Сдвиг картинки на несколько пикселей раз в несколько минут (защита от выгорания) — только OLED (по выбору «Экран
  OLED»: Android тип экрана не сообщает), по умолчанию выключено.

## Часть 5. Второй планшет

- **Файл** (этап 1): «Восстановить из файла копии» на первом экране — нынешний импорт. Токен, пароли и PIN в файле не
  хранятся: после восстановления — вход (часть 1) и пароли камер.
- **QR с другого планшета** (последний этап): на старом — Настройки → «Устройство» → «Скопировать на другой планшет»
  (PIN), на новом — камера не нужна: старый показывает QR и короткий код, новый вводит код и скачивает настройки по
  домашней сети. Содержимое — то же, что в файле копии, зашифровано ключом из кода, страница одноразовая на 10 минут.
- Экран другого размера — предложить масштаб плиток (сейчас размеры в пикселях и не меняются).

## Безопасность

- Новых разрешений, кроме «поверх других окон» (только по запасному пути), нет; новых библиотек нет.
- Пароль Home Assistant вводится только на его собственной странице; панель его не видит и не хранит.
- В журнале и отчётах — без адресов, имён, `uuid`, токенов и паролей.
- Домашняя сеть: только поиск и чтение. Камерам и Home Assistant ничего не меняется (кроме создания доступа по входу
  человека).
- Разрешение «локальная сеть» Android 17 для нас не нужно, пока `targetSdk` 35.

## Что не меняем

Подключение к Home Assistant, хранилище секретов, подписку на события, звонок, видео, разговор, запись, формат копий и
плиток, вид уже настроенных панелей.

слову владельца.

## Стенд Home Assistant

`tools/ha-stand`: настройки и подготовка (пользователи, комнаты). Сам Home Assistant 2026.11.3 — в папке вне
репозитория (`~/StudioProjects/SmartHomeDashboard-ha-stand`, 2,0 ГБ на диске), в систему ничего не ставилось. Пароли
стенда случайные, лежат там же. Сейчас слушает только localhost; для планшета — на время проверки в домашней сети.
Встроенный демо-дом на Mac поднялся не полностью (17 сущностей): к этапу 2 — свои выдуманные сущности.

## Не проверено и риски

- Вход в WebView на Android 7–9 и на Huawei: старый WebView может не открыть страницу Home Assistant — тогда QR или токен.
- Вход с телефона, когда Home Assistant открыт по https, а планшет — по http: браузер телефона может показать
  предупреждение. Проверить на стенде.
- Поиск в сетях с изоляцией клиентов, в другой подсети и через часть роутеров не сработает — остаётся ручной ввод.
- Реальные Xiaomi, Huawei, Lenovo, Pixel Tablet — нет под рукой; тексты по официальным страницам.
- `uuid` в mDNS можно подделать — поэтому решение 6 «спросить».

## Не делаем сейчас

Режим владельца устройства (device owner), розетка для заряда, поиск Hikvision и Dahua по их протоколам (нет камер для
проверки), новые камеры через свои приложения марок, английский язык.
