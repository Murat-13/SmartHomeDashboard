# Диагностика HTTP 403 Яндекс Погоды

## Позднейшее наблюдение: 29 октября 2026 года

При согласованной проверке планшета в штатном журнале предыдущей сборки
обнаружены HTTP 200 и `Forecast updated`. После запуска сборки `1f0c9fa` также
отмечен HTTP 200. В этой проверке ключ, координаты, тариф и настройки провайдера
не менялись, отдельные пробные API-запросы не отправлялись. Причина прежнего 403
не установлена; успешный ответ не объясняет её и не гарантирует будущую
доступность. Владелец отложил дальнейшую погодную диагностику.
Ниже сохранены результаты прежней проверки отказа.

## Проверенное несоответствие запросу API

Приложение передавало сохранённый ключ в `X-Yandex-API-Key`.
В текущей официальной документации REST v2 указан `X-Yandex-Weather-Key`.
Заголовок исправлен; адрес API, координаты, ключ и его хранилище не менялись.
Добавлена безопасная диагностика: только HTTP-код и отметка публикации прогноза,
без URL, ключа, координат и тела ответа.

Официальные источники:
- [Формат REST-запроса](https://yandex.ru/dev/weather/doc/ru/concepts/forecast-rest).
- [Аутентификация](https://yandex.ru/dev/weather/doc/ru/concepts/auth).
- [Возможные причины 403](https://yandex.ru/dev/weather/doc/ru/concepts/errors).

## Проверки

Регрессионный тест правильного заголовка сначала воспроизвёл ошибку, после
исправления прошёл. Добавлена проверка, что 403 не перезаписывает прежний кеш
и не раскрывает ключ/тело ответа в диагностике. Итог: 716 JVM/Robolectric-тестов,
0 failures/errors/skips; assembleDebug и assembleDebugAndroidTest успешны.

С отдельного явного разрешения владельца сборка `81c1d2f` установлена поверх
приложения на Samsung SM-X216B без удаления данных и запущена один раз.
Штатный запрос с сохранённым ключом и исправленным заголовком снова получил
**HTTP 403**. Отметки `Forecast updated` не было; падения не зафиксированы.
Ключ не выгружался на компьютер. Приватные prefs не читались, настройки дома,
ключи, координаты и управление устройствами не затрагивались. Дополнительные
пробные запросы не отправлялись.

Это подтверждает, что исправления заголовка недостаточно для восстановления
доступа конкретного сохранённого ключа. Валидность ключа и причину отказа по
одному HTTP-коду установить нельзя. Причина не считается найденной/исправленной.

## Дальнейшие шаги при повторении HTTP 403

В кабинете Яндекса проверить именно используемый ключ: статус/причину блокировки,
тариф и доступность REST `/v2/forecast`, срок действия, израсходованный лимит.
По документации 403 возможен при отсутствии авторизации, неподходящем URL/тарифе,
истечении срока доступа и превышении лимита. Точный вариант здесь ещё не установлен.
Автоматический доступ к локальному браузеру в текущей среде выключен, поэтому
сведения кабинета запросили у владельца. Сам ключ в сообщениях/репозитории не нужен.

Не менять тариф, не покупать доступ, не заменять ключ и не переключать погодный
протокол до выяснения статуса и согласования решения с владельцем.
