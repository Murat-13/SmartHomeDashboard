# Архитектура панели SmartHomeDashboard

Рефакторинг выполнен от `ci/github-actions` (база `755c64a`) в отдельной ветке
`refactor/main-activity-architecture`. Это изменение структуры существующего UI,
а не переход на новый UI или новый сетевой транспорт.

## Границы компонентов

| Компонент | Ответственность и время жизни |
| --- | --- |
| `MainActivity` | Жизненный цикл, создание окна, навигация/PIN-gate, подсказки, системный kiosk/home режим, запуск чтения HA-токена, связь с контроллером и наблюдение статуса. 531 строка вместо 1582. |
| `MainViewModel` | Владелец соединения и данных HA; публикация `MainUiState`, защита поколением соединения, подключение/отключение обработчиков экрана. Переживает пересоздание Activity. |
| `DashboardDeviceState` | Единственное изменяемое хранилище устройств, атрибутов, частичного прогноза и оптимистических состояний участников групп. Принадлежит ViewModel; не содержит Context/View. |
| `MainUiState` | Снимок для наблюдателей. Карты снимка не изменяются последующим обновлением владельца. Это представление, а не ещё одно изменяемое хранилище Activity. |
| `DashboardDeviceCommands` | Выбор `turn_on/turn_off` и отправка команд, оптимистическое состояние одиночной кнопки/участника группы. Без Context, View и очереди команд. |
| `DashboardPanelController` | Построение и размещение дерева панели, кнопки/группы, события карточек, привязка обработчиков, раскрытие/закрытие и очистка дерева. Один экземпляр на Activity; 772 строки. |
| `DashboardContentController` | Обновление часов, погоды HA/Яндекса, показаний и фона сенсоров/батареи через существующие рендереры; подробный прогноз и его прокрутка. 185 строк. Не запускает сеть. |
| `SensorWindowTouchHandler` | Перехват касаний раскрытой карточки, прокрутка, закрывающий тап, ACTION_CANCEL и остаток прерванного жеста. Не знает Activity. |
| `SensorExpansionSession`, `SensorResizeHandler`, `TileEditDragHandler` | Существующие анимации раскрытия, resize/rollback и edit-drag/rollback. Используются контроллером, их алгоритмы не переписаны. |
| `HomeAssistantWebSocket` | Авторизация, адреса и возврат на локальный HA, backoff, события, состояния, прогноз и `call_service`. В этом рефакторинге файл не менялся. |
| `TileManager`, `PanelEntityIds`, `PanelSubscriptionPlan` | Существующие хранение плиток, зависимости видимых сущностей и план подписок. Не заменены дублирующими реализациями. |

## Поток данных

1. Сетевой клиент доставляет событие в ViewModel на главном потоке.
2. ViewModel проверяет поколение, один раз обновляет `DashboardDeviceState` и
   публикует снимок. Старое соединение не может перезаписать новое.
3. Подключённый экран получает явное событие для отрисовки. Короткие события
   движения не зависят от conflation `StateFlow` и не пропадают между снимками.
4. Контроллеры читают текущее состояние владельца. Отдельных копий `singleStates`,
   `groupStates`, `entityAttributes`, `syntheticForecasts` в Activity больше нет.
5. Статус остаётся состоянием `StateFlow`: Activity наблюдает его между
   `onStart/onStop`, с `distinctUntilChanged`. Нет записи статуса в prefs на каждое
   событие датчика. Новые lifecycle-библиотеки не добавлены.

Callback экрана и StateFlow имеют разные задачи. Заменять оба механизма одной
механической подпиской нельзя: потеря промежуточного события движения меняет
поведение настенной панели.

## Команды и группы

Одиночное нажатие немедленно вызывает `call_service`, затем меняет оптимистическое
значение кнопки. Нажатие дочерней кнопки меняет оптимистическое значение участника
группы, сохраняя отдельно фактическое одиночное состояние до события HA.
Групповая команда по-прежнему отправляется каждому элементу списка в исходном
порядке, включая дубликаты. Групповое нажатие не подменяет фактические состояния
всех устройств. Удалённые участники исключаются при актуализации состава; добавленные
берут уже известные значения. Реальное событие HA заменяет оптимистическое значение.
Транспорт не хранит действия для повторной отправки после восстановления сети.

## Жизненный цикл и очистка

Контроллеры создаются лениво и принадлежат конкретному экрану. Их `Host/Sources`
содержат зависимости UI и callback навигации; во ViewModel эти интерфейсы не
передаются. View создаются с исходным Context Activity, а не с Context контроллера.

При перестроении панели отменяются таймеры/long-press, resize и drag, анимации
старых View, слушатели касаний/кликов и раскрытие. Учитываются также дочерние кнопки,
которые ещё заканчивают анимацию закрытия. Положение прогноза сохраняется при
обновлении того же источника и сбрасывается при смене источника/закрытии карточки.

В `onDestroy` Activity очищает панель, таймеры экрана и обработчики ViewModel.
Само соединение остаётся у сохраняемого ViewModel и закрывается в `onCleared`.
После пересоздания новый контроллер читает текущие данные сразу, без копирования
карт и ожидания следующего события HA. Старые callback освобождаются, а события
без подключённого UI всё равно обновляют данные.

## Сохранённые требования

Не изменены форматы конфигураций, ключи prefs, импорт/экспорт, applicationId,
namespace, зависимости/SDK, SecretStore/Keystore, параметры и хранилище PIN,
миграция удаления MQTT, дизайн и сетевой протокол. Периодический запрос погоды
Яндекса остаётся в жизненном цикле Activity: сразу при resume и затем раз в час.
Контроллер содержимого только отображает уже полученные данные.

## Проверки

Исходный baseline: 703 JVM/Robolectric-теста, 0 failures/errors/skips; обе debug
сборки успешны. Baseline-команда использовала существующий Gradle-кеш; её время
не является измерением скорости тестов или приложения.

После каждого из шести этапов выполнялись задачи:

```bash
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline
```

Этапы: единый владелец данных (705 тестов), команды (709), касания раскрытой
карточки (711), панель (713), содержимое (713), итоговая lifecycle-проверка (714).
Все итоговые проверки каждого этапа прошли. Существующие тесты сохранены; доступ
reflection-фикстур следует за переносом методов/свойств через `ArchitectureTestAccess`.
Новые тесты фиксируют стабильность снимков, состав групп, семантику команд,
отмену жеста, независимость контроллера от MainActivity, Context View, очистку
старых listeners и освобождение callback в настоящем `onDestroy` Robolectric.

Сборка `assembleDebugAndroidTest` проверяет компиляцию и упаковку инструментальных
тестов. На устройстве инструментальные тесты здесь **не запускались**.

## Производительность и оставшиеся ограничения

Устранены четыре отдельные карты данных Activity и их копирование при создании/
возврате экрана. Видимость по `PanelEntityIds` по-прежнему кешируется до изменения
списка плиток или motion entity. Тесты `PanelEventFilterTest` подтверждают отсутствие
перерисовки для посторонних событий. Существующие тесты погоды подтверждают, что
тик часов не перестраивает подробный прогноз и что прокрутка не теряется.

Это измеримые структурные/событийные проверки, а не доказательство ускорения на
Samsung. CPU, память и работа сутками на реальном устройстве не профилировались.
Известные значения невидимых сущностей сохраняются: их очистка сломала бы
немедленное заполнение добавленной плитки. Для огромного/динамичного набора
сущностей нужна отдельная политика кеша с проверкой совместимости. Обход групп и
разбор их JSON при релевантном событии пока сохранены; индексировать их стоит
после профилирования, отдельно от переноса ответственности.

ViewModel пока использует `JSONObject/JSONArray` и явные callback доставки событий.
Полностью типизированная immutable-модель — возможный отдельный этап, а не условие
этого переноса. Контроллер панели остаётся самым крупным UI-компонентом; дальнейшее
дробление layout/анимаций оправдано при конкретном изменении функции, с текущими
регрессиями. Чтение токена и проверка актуальности конфигурации остались частью
lifecycle-координации Activity; транспорт и данные от UI отделены.

На планшете нужно проверить обновление поверх установленной версии без удаления
данных, HA при потере сети/смене адреса/токена и возврате на локальный адрес,
пересоздание/возврат экрана, одиночные и групповые кнопки, edit/drag/resize/cancel,
карточки и прокрутку прогноза, HA/Яндекс погоду и часовой refresh, motion/kiosk/home,
PIN-gate, импорт/экспорт. Проверку планшета выполняет владелец; приложение и данные
физического устройства этим рефакторингом не читались и не запускались.
