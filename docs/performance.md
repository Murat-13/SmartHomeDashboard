# Производительность HA и панели: воспроизводимый сценарий

База измерения — `49c7cf9`, код установленной рабочей версии `1f0c9fa`.
Сценарий: `DashboardPerformanceScenarioTest.syntheticInitialLoadAndSensorBurst`.
Только искусственные данные, записывающий WebSocket без сети, Robolectric SDK 28.
Это in-process JVM-время, не Android frame time, не FPS и не задержка реального HA.

Команда отдельного сопоставимого запуска:

```bash
./gradlew testDebugUnitTest --offline --tests '*DashboardPerformanceScenarioTest'
```

На каждый размер — два общих прогрева по 100 сущностей, затем пять независимых
снимков; приводится медиана. Измеряется разбор JSON-ответа, доставка в ViewModel,
обновление хранилища и публикации, без генерации исходного payload и без сети.
Отдельный сценарий строит 20 карточек с разными источниками и измеряет одно
событие, затем 200 событий пяти источников. Число затронутых карточек определяется
по чтениям их источников, число новых TextView — по идентичности объектов дерева.
Никаких временных порогов прохождения теста нет; корректность конечных значений
проверяется утверждениями. Данные не являются результатом профилирования Samsung.

## Пакетная загрузка

`HaInboundMessage` разбирает JSON и подготавливает массив на существующем
последовательном reader OkHttp. Новые потоки и фоновые coroutine-очереди не созданы.
`HaMessageGate` допускает не более 32 ожидающих доставок на соединение: reader
ожидает свободный слот вне UI, события не conflated и не выбрасываются. Отмена
соединения освобождает ожидающий reader; callback главного потока проверяет
поколение и всегда освобождает слот, включая устаревшую доставку.

`get_states`, список реестра, сервисы и прогнозы сопоставляются с командой по ID.
Начальный снимок не заменяет сущность, которая получила событие или принятую
команду после запроса. Текущие ожидающие команды учитываются и при новом запросе.
Более новый синтетический прогноз сохраняется без потери остальных полей погоды.
Повторный/устаревший ответ состояний игнорируется. Для перекрывающихся запросов
реестра сохраняется ограниченный набор из 32 ID; более новый полученный список
инвалидирует старые ответы. Однократное ожидание чтения ограничено 30 секундами;
повторных запросов по таймеру нет, при отмене/смене соединения учёт очищается.

ViewModel применяет все строки к единому `DashboardDeviceState` и публикует один
согласованный снимок, включая начальное согласование UI-групп. MainActivity
подключает отдельный batch-callback; обычные `state_changed`, в том числе короткое
движение, по-прежнему доставляются явно и немедленно, независимо от StateFlow.
Для остальных клиентов WebSocket прежний поэлементный callback сохранён.

Проверены пустой ответ, 1/100/500/1000/2000 строк, повреждённые элементы,
перекрывающиеся/повторные ответы, события/команды/прогноз после запроса, смена
поколения, detach, отмена ожидающего reader и ограничение учёта реестра.
Локальный MockWebServer доставил 2000 начальных сущностей и 100 чередующихся
переходов движения: все callbacks в главном потоке, порядок сохранён.
Полная проверка этапа: 767 тестов, 0 failures/errors/skips, обе debug-сборки успешны.

Частные адаптеры reflection-тестов следуют за подготовленным сообщением, assertions
сохранены. Старый некоррелированный ответ фикстуры получил реальный ID запроса;
фикстура более нового полного снимка после события теперь явно делает новый
запрос. Порогов времени и production-логирования показаний не добавлено.

## Адресное обновление

`PanelEntityIds.describe()` задаёт единую консервативную зависимость каждой плитки:
основные/свёрнутые/раскрытые источники, SOC, правила цвета, группы и дополнительные
JSON-поля. Погодный fallback относится только к погодной карточке, не ко всем
сенсорам. `PanelDependencyIndex` инвертирует этот набор в entity → плитки и
объединяет пакет без дубликатов. Для повреждённой конфигурации пересчитывается
только сомнительная карточка; совместимые массивы расширенных полей не считаются
повреждением. Неизвестные строковые поля учитываются избыточно ради совместимости.

Индекс заменяется при смене неизменяемого списка TileManager и motion-source;
обычный refresh после настроек/импорта также очищает его. Существующий TileManager
проверяет строку prefs и замечает запись другим экземпляром/прямой импорт.
Кеш tileId → View содержит только текущее дерево и очищается при teardown.
При отсутствующем/отсоединённом View выполняется ограниченное восстановление по
живым прямым детям панели. Нет истории старых конфигураций или глобального кеша Views.

Обычный state_changed и начальный пакет обновляют только объединение зависимых
контролов и карточек через `DashboardContentController.updateTiles`. Пробуждение
от движения выполняется перед отрисовкой; командное восстановление затрагивает
только контролы. Прогноз обновляет соответствующие погодные карточки, не чужой
открытый прогноз. Полные методы сохранены для явной перестройки, callback Яндекса
и существующего 10-секундного тика часов. Алгоритмы жестов/анимаций не менялись.

Промежуточный тот же сценарий: 1 карточка вместо 20 на событие, 1 новый TextView
вместо 20; 200 строк за 200 событий вместо 4000. Переиспользование строк ещё не
включено. Подтверждены все виды источников, инвалидация правил/групп/импорта,
раскрытие, отдельный SOC, независимые прогнозы и очистка старых View-ссылок.
Полная проверка этапа: 785 тестов, 0 failures/errors/skips, обе debug-сборки успешны.
Два старых ожидания перестройки прогноза от постороннего датчика заменены на ноль
перестроений с дополнительной проверкой идентичности дерева и позиции прокрутки.
Остальные проверки прогноза и его обновлений сохранены.

## Переиспользование строк

`SensorContentRenderer` сначала подготавливает все значения, затем обновляет
только изменившийся текст существующих строк. При неизменной структуре сохраняются
TextView, LayoutParams, стиль и заголовок; размер шрифта меняется только при
необходимости. Владение строкой отмечено локальным keyed-tag, глобального кеша
Views нет. Изменение структуры добавляет/убирает только необходимые строки;
исключение formatter оставляет прежнее дерево и значения нетронутыми.

Проверены идентичность, отсутствие повторных requestLayout при одинаковых
данных, структура/порядок строк, шрифт/стили, ошибка форматирования и обновление
во время продолжающейся анимации родителя. Тест анимации использует управляемые
16-мс кадры Robolectric. Существующие проверки resize, раскрытия, батареи,
погоды и отмены жестов сохранены. Полная проверка: 791 тест, ноль
failures/errors/skips, debug APK и AndroidTest APK собраны.

callbacks, порядок движения, конечные значения и атрибуты, состояния группы,
неизменность исходного опубликованного снимка и постоянные размеры хранилищ
на фиксированном наборе ID. Это ограниченная проверка структуры данных,
не замер Android heap и не доказательство отсутствия любых утечек.

Ещё один сценарий выполнил 20 циклов detach/замены соединения: ожидающие

## Оставшиеся границы и проверка на планшете

- Снимок обычного события по-прежнему копирует карты текущих сущностей. Это
  сохраняет контракт MainUiState; при существенно большей нагрузке стоимость
  стоит профилировать отдельно. Исторические версии в production-кеш не складываются.
- Состояния всех известных HA-сущностей сохранены для мгновенного создания новых
  плиток. Автоматического удаления невидимых сущностей не вводили. Размер такого
  хранилища зависит от набора HA entity_id; тест не доказывает ограничение при
  бесконечном появлении новых ID на сервере.
- Ограничение 32 сообщений — ограничение числа ожидающих доставок, не байтов
  одного произвольно большого JSON. При перегрузке reader применяет backpressure;
  события не теряются, но задержка на физическом устройстве требует измерения.
  Построение JSONObject не прерывается посреди разбора, однако подготовка массива
  и применение проверяют отмену/поколение.
- 60/90/120 FPS, Android heap, длительные кадры, аппаратная задержка и работа
  24/7 не проверены. Инструментальный APK собран, инструментальные тесты на
  планшете не запускались. Установка и реальные управляющие команды не выполнялись.

Перед принятием на планшете: записать frame time/jank и heap до/после нагрузки;
проверить раскрытие, прокрутку прогноза, resize и отмену касаний на фоне частых
показаний; пересоздание экрана, добавление/редактирование/импорт плиток и
немедленное отображение известных данных; потерю/восстановление связи и смену
адреса; краткое движение; длительную работу 24–72 часа. Сетевые сценарии и
команды проверять на тестовом HA либо отдельно согласованным владельцем способом.
Настройки, токены, PIN и данные действующего дома в этом этапе не менялись.

Изменения остаются локально в main, публикации GitHub и релиза не выполнялись.
