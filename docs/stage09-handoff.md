## 2. Как работать с владельцем

- Общение на русском. Владелец сам проверяет каждый этап на Samsung SM-X216B (Android 16) и пишет результат.
- **Тесты и сборки запускать без вопросов**: владелец прямо попросил не спрашивать.
- **Спрашивать обязательно**: перед любым действием на планшете, перед push (если владелец не разрешил в
  текущем сообщении), перед чем-либо, что касается реального дома, ключей и паролей.
- Вопросы — интерактивными вариантами (инструмент выбора ответа): так просил владелец.
- Один этап → полный прогон тестов → запись в журнал `AGENTS.md` → локальный коммит → отчёт → остановка.
- Не обещать «тихое обновление готово», пока не проверено на планшете. Чеченский планшет **не трогать**:
  только после визита владельца и успешного пилота в Москве.

## 5. Согласованные решения по этапу 09 (FINAL_TZ, раздел 7)

- `versionName`: 0.9.x до полной регрессии (этап 10), затем 1.0.0, дальше 1.0.1…; `versionCode` строго растёт.
- **Новый release-ключ.** Создаёт и хранит владелец: в Git, логах и чате его нет; резервная копия ключа — у владельца.
  Планшеты **один раз переустанавливаются**: «Сделать копию сейчас» / экспорт → удаление → установка → импорт →
  ввод токена HA, ключа Яндекса и PIN. Москва — владелец; Чечня — при визите, до него не трогать.
- **Источник — GitHub Releases** (`Murat-13/SmartHomeDashboard`): подписанный APK, описание, SHA-256. Проверить,
  публичный ли репозиторий; если приватный — спросить владельца, токен на планшет не класть без решения.
- **Каналы**: тестовый (Москва) и стабильный (Чечня), выбор в «О приложении». В стабильные — решением владельца,
  не раньше чем через 3 дня работы версии в тестовом канале.
- **Установка**: проверить обновления → скачать по HTTPS → проверить хэш и подпись (сертификат совпадает с
  установленным) → копия «перед обновлением» → тихая установка, если Android разрешает (PackageInstaller,
  самообновление, `USER_ACTION_NOT_REQUIRED`, Android 12+). Иначе в боковой панели «Доступно обновление» →
  PIN → «Установить». `STATUS_PENDING_USER_ACTION` **не считать успехом**. Сначала — эксперимент на московском
  планшете с разрешения владельца.
- Если копия перед обновлением не удалась, установка на паузе. Админ может продолжить по PIN после предупреждения;
  это фиксируется в журнале приложения.
- Недоступный GitHub, обрыв сети, полный диск, неверная подпись или неудачный бэкап не мешают управлять домом.

## 6. Предлагаемое деление (каждая часть — отдельный коммит и отчёт)

- **09а** — подпись и версии: `signingConfigs.release` из `keystore.properties` вне Git (файл в `.gitignore`,
  чтение без падения, если файла нет), `versionCode/versionName`, инструкция владельцу: как создать ключ
  (`keytool`), где хранить, как собрать release, как переустановить. CI не трогать без решения.
- **09б** — проверка обновлений: клиент GitHub Releases API, выбор канала, сравнение `versionCode`, загрузка по
  HTTPS во внутреннюю папку, SHA-256, проверка подписи APK (`PackageManager.getPackageArchiveInfo` +
  сертификаты), копия перед обновлением, статус в «О приложении» и боковой панели. Тесты на MockWebServer.
- **09в** — установщик: `PackageInstaller` session, обработка `STATUS_*`, путь с подтверждением, журнал. Проверка на
  планшете — только владельцем или с его разрешения.
