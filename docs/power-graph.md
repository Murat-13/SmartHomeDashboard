# График мощности в карточках «Электропитание Modern» (0.9.4)

ТЗ владельца: `SmartHomeDashboard_TZ_Inverter_Power_Graph.md` и эскиз (вне репозитория, в «Загрузках»).
Этот файл — архитектура и решения до изменения работающего поведения (п. 9.2 ТЗ), затем — ход работ.

## Решения владельца (03.11.2026)

- График — в **обеих** карточках электросети (`power_modern`: «Сеть · Вход» и «Инвертор · Выход»).
- Источник графика по умолчанию — **датчик мощности карточки** (строка `power`); в редакторе можно выбрать другой.
- Пишется история только **текущих** источников; архив прежнего датчика хранится 35 дней (на время,
  пока он не выбран, — пробел).
- Отдельный бэкап истории — **раз в сутки, 3 копии**.
- Линия между замерами — **плавная** (линейная), но без соединения через разрывы.
- Выбранная вкладка периода — **своя у каждой карточки**, по умолчанию `1ч`.
- Автозакрытие раскрытой карточки — прежние **30 с после последнего касания**; касания графика и
  полноэкранного графика перезапускают таймер.
- Работа этапами без остановок, в конце **одна версия 0.9.4**. Номер 0.10.0 не используется.

## Технические решения

- **Хранилище** — встроенный `SQLiteOpenHelper`, файл `power_history.db` (без новых зависимостей).
  Исключён из Android Backup (большой, есть свой бэкап). Все запросы — на отдельном потоке.
- **Сервер HA** различается ключом `instance` = первые 16 символов SHA-256 от полей ответа `get_config`
  (название, часовой пояс, координаты). Адреса не участвуют — локальный/внешний адрес одного сервера
  не делят историю; сами координаты не хранятся.
- **Таблицы:** `source(id, instance, entity_id)` — уникально по паре; `raw(source, ts, value)` — PK (source, ts),
  `value = NULL` — начало разрыва; `minute(source, start, min, max, avg, covered_ms, count)` — для данных
  старше 7 дней; `alive(source, until)` — до какого момента запись точно шла.
- **Разрывы.** HA присылает значение только при изменении, поэтому долгое отсутствие событий не разрыв.
  Разрыв — это потеря связи, `unavailable/unknown`/нечисло, остановка приложения (по `alive.until`),
  смена источника. Линия и заливка через разрыв не рисуются.
- **Запись.** `MainViewModel` передаёт состояния (снимок и `state_changed`) регистратору, тот фильтрует по
  текущим источникам, приводит Вт/кВт (по `unit_of_measurement`) к Вт без смены знака, отбрасывает повторы
  и метки времени из будущего/далёкого прошлого и пишет пачками. Время замера — `last_changed`/`last_updated`
  из HA, если есть, иначе время получения.
- **Агрегация.** Фоново (при запуске и раз в час): сырые точки старше 7 дней → минутные агрегаты
  (min/max/среднее по времени/покрытие) и удаление сырых в одной транзакции; данные старше 35 дней удаляются.
  Минутные данные на сильном увеличении показываются полосой min–max с подписью «точность 1 мин».
- **История из HA.** После подключения — `history/history_during_period` (только чтение,
  `minimal_response`, `no_attributes`) за участки без локальных данных, не глубже 35 дней (HA обычно
  хранит ~10). Точки вставляются без перезаписи существующих.
- **Статистика** (Мин/Макс/Средняя) — за весь период вкладки, не за видимый после zoom участок;
  средняя — взвешенная по времени, значение держится до следующего замера, разрывы не учитываются;
  мало данных — «—». «Сейчас» — последний достоверный замер источника графика.
- **Периоды:** `1м`/`1ч` — скользящие; `Сутки`/`Неделя`/`Месяц` — календарные (с полуночи, с понедельника,
  с 1-го числа) в часовом поясе планшета, через `java.time` (учёт перехода на летнее время).
- **Отрисовка** — собственная `PowerGraphView` (Canvas, без выделений в `onDraw`), прореживание только
  для экрана (min/max на пиксель), автомасштаб по видимому участку с обязательным 0 Вт и гистерезисом.
  Голубой > 0, зелёный < 0, цвет меняется точно в точке пересечения нуля.
- **Жесты** — один палец: прокрутка; два пальца: масштаб по времени вокруг середины; касание — курсор;
  перетаскивание от линии курсора (зона 48dp) двигает курсор. Двухпальцевая навигация панели при
  раскрытой карточке уже отключена — конфликта нет.
- **Раскрытая карточка:** справа сверху — существующие строки (компактнее), под ними «История мощности».
  Карточка уже занимает почти всю высоту экрана, поэтому выше её не делаем; если места мало —
  прокрутка правой колонки. Полноэкранный график — слой поверх приложения (не Activity) с общим
  состоянием просмотра.
- **Бэкап истории** — отдельный WorkManager-задание ~04:00, файл `smarthome_power_history_<дата>.json.gz`
  (версия формата, SHA-256 содержимого, ключи `instance`+`entity_id`) в выбранную SAF-папку (иначе —
  внутренняя папка, как у копий настроек). Новый файл пишется полностью и проверяется чтением, затем
  удаляются старые сверх 3. Восстановление — в «Настройки → Устройство», с выбором копии,
  вставкой без перезаписи более новых данных. Токен/PIN/адреса в файл не входят. Бэкап настроек не меняется.

## Этапы

1. Данные: база, регистратор, агрегация, статистика, выбор источника в редакторе, история из HA.
2. Отрисовка и жесты, раскрытая карточка с графиком.
3. Полноэкранный график.
4. Бэкап и восстановление истории.
5. Регрессия, снимки на тестовых данных, версия 0.9.4.
