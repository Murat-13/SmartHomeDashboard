# «Сохранить и выйти» после восстановления копии (0.9.2, этап 4)

## Наблюдение владельца (один раз, московский планшет)

Чистая установка → адрес и токен HA → импорт сохранённой конфигурации → плитки восстановились, связь работала →
«Сохранить» в диалоге ухода из настроек выполняло действие, но экран оставался; повтор не помогал; выход удался
только через отказ от сохранения; панель затем работала.

## Восстановленная последовательность (по коду, подтверждена тестами до исправления)

1. Импорт файла с адресом HA, отличным от текущего, предлагает «Проверить и применить». Выбор подставляет адрес из
   файла в поля «Соединений» и запускает пробное подключение (`saveConnections`).
2. Если проба не удалась, причина писалась только строкой статуса в разделе «Соединения». Поля оставались с адресом
   из файла — форма считалась несохранённой (`haChanged`).
3. «Назад» → «Сохранить изменения?» → «Сохранить» снова запускало ту же пробу → снова неудача → экран на месте.
   Цикл; выйти можно было только «Не сохранять» (прежний адрес, восстановленные плитки — панель работает).

Вторая, независимая ошибка того же пути: при **успешной** пробе `saveCurrentSettings` записывал в настройки значения
полей формы, открытой до импорта (тайм-аут экрана, °C/°F, киоск, виброотклик, сессия PIN, координаты Яндекса), —
импортированные значения тихо перезаписывались старыми. Тест до исправления: тайм-аут 9 из файла → 5 из формы.

Остальные места молчаливого прерывания сохранения (чтение погоды не завершено, неверная длительность сессии в
другом разделе, ошибка токена/погоды) тоже писали причину только в строку своего раздела.

Причина единичного случая на планшете однозначно не установлена (журнала устройства нет): описанный путь —
единственный найденный в коде, который даёт ровно такое поведение. Почему проба к адресу из файла не прошла,
неизвестно (например, другой формат адреса или внешний адрес недоступен из сети планшета).

## Исправление

- `SaveFlow` — откуда запущено сохранение: обычное / при уходе / адрес из импорта. `saveFailed(причина)`:
  - **адрес из импорта**: поля возвращаются к сохранённому адресу, диалог «Адрес из файла не применён» с причиной и
    «Продолжить» → перезапуск панели (плитки и настройки из файла уже восстановлены, текущий адрес оставлен);
  - **при уходе**: диалог «Не удалось сохранить» с причиной: «Остаться» / «Выйти без сохранения»;
  - **обычное**: причина ещё и всплывающим сообщением.
  Успешное сохранение адреса из импорта завершается перезапуском панели (как импорт без смены адреса), иначе — выход.
- После импорта форма перечитывается из настроек (`refreshFormAfterImport`, координаты Яндекса — повторным чтением),
  поэтому сохранение не возвращает старые значения. Адрес HA — по-прежнему только по согласию и после проверки.
- Сохранение во время чтения настроек Яндекса не обрывается, а продолжается после него.
- Токен HA и ключ Яндекса не удаляются и не перезаписываются (проверяется в тестах).
- Текст диалога экспорта и подсказка в «Устройстве»: файл содержит адреса HA и координаты, но не токен, ключ Яндекса и PIN.

## Проверки

`SettingsImportSaveTest` с локальным поддельным HA (MockWebServer): импорт с тем же адресом → перезапуск, затем
«Сохранить» выходит без цикла; принятый адрес из файла сохраняется только после проверки и не портит импортированные
настройки; недоступный адрес из файла → объяснение, текущий адрес, перезапуск; неудачное сохранение при уходе →
причина и выход без сохранения; текст экспорта. До исправления 4 из 5 тестов падали ровно на описанных местах.
На планшете не проверено.
